# 内网设备发现与远程工作区

多台设备在同一内网运行 cmux 时，本机自动发现其他设备，并能打开远端已有的工作区，查看终端输出、发送输入和继续操作正在运行的 agent。工作区镜像、终端协议、加密连接和会话行为尽量复用 cmux 的现有实现。

状态：需求与设计草案，尚未实现。

日期：2026-10-10。

Fork：[St0neWan9/cmux](https://github.com/St0neWan9/cmux)。

上游：[manaflow-ai/cmux](https://github.com/manaflow-ai/cmux)。

## 首期范围

- 多台设备位于同一内网，网络允许设备互通和服务发现。首期以多台 Mac 运行 cmux macOS App 为基线。
- 自动列出内网中开启设备访问的 cmux 实例，展示设备名称、在线状态和兼容性。
- 用户选择设备和工作区后，将远端已有会话显示为本地 cmux 工作区。agent 和 shell 继续在远端执行。
- 复用现有终端输出、键盘输入、工作区布局、分屏、标签、滚动历史和通知机制。
- 内网模式使用本地发现、明确的设备授权与直连，不以官方账号、Pro 订阅或 Cloud Machines 激活为启用条件。
- 本次仓库准备只新增此文档。后续实现另行开展。

公网连接、跨网段发现、云端中继、自建官方控制服务、iOS 和 Linux 客户端适配不属于首期范围。远端 cmux App 保持运行是首期会话可访问的前提。

## 已确认的上游机制

以下结论来自此前对 cmux **v0.65.0** 的源码和文档检查。Fork 基于上游默认分支；开始开发时，需要重新确认对应代码在当前分支的位置和行为。

| 部分 | 当前机制 | 内网模式需要处理的边界 |
| --- | --- | --- |
| Devices 启用 | `DevicesFeature.isAvailable` 依赖 `CloudMachinesFeature.isEnabled` | 为内网模式建立独立启用条件，保留适用的设备发现、入站访问和网络管理策略 |
| 设备发现与授权 | 原生 Devices 从账号对应的控制服务读取设备目录和连接授权 | 以局域网发现提供候选设备，以本地配对提供可信授权 |
| 远程传输 | Devices 复用 Iroh/irx endpoint、连接准入和远程会话协议 | 使用已发现的内网地址直连，并复用现有加密通道 |
| 会话展示 | 已有设备、工作区、终端镜像与布局投影代码 | 复用这些代码，避免另建一套终端或聊天界面 |

## 使用流程

1. 设备 A 在 cmux 中开启内网设备访问，发布发现信息，并继续运行已有工作区和 agent。
2. 设备 B 开启内网设备发现，自动看到设备 A。
3. 用户在 B 选择 A。首次连接通过配对或远端确认建立信任；之后使用已保存的设备身份。
4. B 获取 A 的工作区列表，选择一个工作区并打开镜像。
5. B 显示同一远端会话的输出，输入由 A 的原有终端进程处理。布局、通知及会话操作遵循 cmux 现有语义。
6. B 断开连接时释放本地镜像连接。远端工作区继续按 cmux 原有生命周期运行；重连时重新订阅同一远端会话。

## 拟采用的架构

```text
Mac A：cmux 工作区与 agent
       │ 发布局域网发现信息
       │
       └──── 现有加密远程会话通道，使用内网地址直连 ────┐
                                                     │
Mac B：自动发现设备 → 配对授权 → cmux 工作区镜像       │
       └─────────────────────────────────────────────┘
```

### 局域网发现

拟使用 Bonjour/mDNS；具体服务类型、发布端口和 Swift/原生桥接接口在实现前确认。

发现记录应包含连接所需的最小信息：实例标识、显示名称、协议版本、endpoint 身份和可用内网地址。设备名称仅用于展示，可信身份以配对确认的公钥或现有 endpoint 标识为准。

发现模块负责上线、下线、地址变化和实例去重，并将结果适配到现有设备目录或 provider 层。处理多网卡、同名设备、网络切换和不兼容协议版本，不在 mDNS 信息中发布终端内容或凭据。

### 配对与连接准入

发现设备不等于获得终端访问权限。优先复用 cmux 的配对存储、身份校验、准入握手、权限检查和撤销机制。

上游有些准入判断依赖官方服务签发的数据。内网模式需要提供独立的本地授权来源，将用户确认和已配对的设备身份接入现有验证边界；不能用伪造官方授权或关闭身份校验来代替这一步。

首次配对的具体交互在接口调查后确定，目标是一次明确确认后保存信任，并支持撤销和设备身份变化后的重新确认。

### 直连与会话复用

优先复用 Iroh/irx 的加密传输、远程 workspace/terminal 协议、输入输出流和恢复机制。内网地址与可信身份由本地发现及配对提供，传输无需官方设备目录或中继凭据。

需要确认现有 endpoint supervisor 能否在不启动官方控制服务的情况下创建、监听并接收直连地址；若当前初始化耦合较深，应抽出可复用的本地连接初始化路径。

工作区、分屏、标签、滚动历史、通知、尺寸协调和远端对象标识继续由既有实现管理。关闭远端对象等操作保持原有权限和会话语义，开发时需明确区分本地断连与远端关闭。

### 功能入口

为 Devices 增加独立的内网模式和本地开关，分别控制发现其他设备与允许本机接受连接。已有官方账号连接方式保持原有开通和权限逻辑。

界面复用现有 Devices/工作区展示，避免因 Cloud Machines 未激活而隐藏内网设备。所有新增产品字符串遵循仓库的本地化规范。

## 后续实施顺序

1. **接口调查**：梳理设备目录、provider、endpoint 初始化、配对及准入验证，确认可复用边界和上游已有相关改动。
2. **独立内网模式**：建立独立状态与入口，保留设备发现、入站访问和网络相关管理策略。
3. **发现与可信连接**：实现 Bonjour/mDNS 适配和本地授权来源，打通两台 Mac 的现有加密会话协议。
4. **工作区镜像**：接入既有镜像、输入输出、布局、通知与重连机制。
5. **验证与发布**：运行覆盖实际改动的检查，在两台内网 Mac 上验证；开发构建使用独立 bundle/tag，不替换日常使用的 cmux。

## 首期验收标准

以下是后续开发的验收要求，当前尚未执行。

- 两台内网 Mac 开启对应开关后能自动发现对方；关闭入站访问后停止接受新连接。
- 首次连接经过明确授权，已配对设备可以重连；撤销授权后无法继续访问。
- 设备 B 打开的是 A 已有的终端进程，能看到持续输出，并向同一进程发送输入。
- 多个工作区、标签和分屏能够映射，滚动历史、通知和尺寸变化遵循既有机制。
- 客户端断连、重连和多客户端操作不误关闭远端会话；生命周期行为有明确验证。
- 网络切换、设备下线、身份变化和协议不兼容时，界面显示可理解的状态并正确清理连接。
- 不依赖官方账号、订阅、设备目录和中继服务即可完成内网连接；此项必须用运行证据确认。
- 不新增面向所有内网设备的无认证终端控制入口，适用的管理策略仍生效。

## 待确认事项

- Bonjour 的服务类型、发现元数据、网络权限与多网卡地址选择。
- 同一远端终端被多个客户端打开时，焦点、输入和尺寸如何沿用现有规则。
- 配对状态与设备身份的保存位置，以及撤销后的活动连接处理。
- 哪些镜像能力已有行为覆盖，哪些必须补充两机运行验证。
